# Уборка дома

Самостоятельное веб-приложение для совместной организации домашних обязанностей. Frontend: React + TypeScript + Vite. Backend: NestJS + Prisma + PostgreSQL. Синхронизация: Socket.IO. Firebase и Google Authentication не используются.

## Возможности

- Регистрация по email и паролю, подтверждение почты, вход/выход, восстановление и смена пароля.
- Домашние группы с владельцем и участниками, приглашение по коду, удаление участников и выход из группы с передачей владения.
- Календарь с месячным и недельным режимами, заданиями, датой, временем, исполнителем и описанием.
- Создание, изменение, удаление и отметка выполнения заданий.
- История выполнений и рейтинг: +10 за выполнение, −3 за просроченное назначенное задание.
- Автоматическое обновление данных в открытых сессиях через Socket.IO.
- Адаптивный интерфейс для телефона, планшета и компьютера; оригинальные иллюстрации собачки сохранены.

## Локальный запуск через Docker (самый простой способ)

Требуется Docker с Docker Compose.

```bash
cp .env.example .env
cp backend/.env.example backend/.env
```

В `backend/.env` задай случайный `JWT_SECRET` длиной не менее 32 символов. Пароль PostgreSQL в `DATABASE_URL` должен совпадать с `POSTGRES_PASSWORD` в корневом `.env`. Затем:

```bash
docker compose up --build -d
```

Открой `http://localhost:8080`. В development без SMTP API вернёт одноразовый токен подтверждения/сброса прямо в форме; это только режим локальной разработки.

## Запуск frontend/backend отдельно

Требуется Node.js 22+ и npm. Запусти базу: `docker compose up -d db`. Для запуска backend напрямую на компьютере измени hostname в `backend/.env` `DATABASE_URL` с `db` на `localhost`, затем:

```bash
cd backend
npm install
npx prisma generate
npx prisma migrate dev
npm run dev
```

В другом терминале из корня проекта:

```bash
npm install
npm run dev
```

Vite доступен на `http://localhost:3000` и проксирует `/api` и `/socket.io` на backend.

## Почта

Для публичной регистрации настрой SMTP в `backend/.env`: `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASS`, `MAIL_FROM`, `APP_URL`. Без SMTP в development API возвращает одноразовый токен для ручного подтверждения. В production без SMTP регистрация и отправка восстановления пароля не выполняются.

## Публикация в интернете

Код включает Nginx reverse proxy и отдельную конфигурацию Caddy для автоматического HTTPS. Понадобится VPS/хостинг с Docker, DNS-имя (собственный домен или выданный хостингом поддомен) и SMTP.

1. Создай корневой `.env` из `.env.example`, укажи `SITE_DOMAIN` и сильный `POSTGRES_PASSWORD`.
2. Создай `backend/.env` из `backend/.env.example`; укажи `NODE_ENV=production`, случайный `JWT_SECRET`, `DATABASE_URL` с тем же паролем БД, `APP_URL=https://SITE_DOMAIN`, `CORS_ORIGIN=https://SITE_DOMAIN` и SMTP-параметры.
3. Направь DNS A/AAAA домена на VPS.
4. Выполни `docker compose -f docker-compose.yml -f docker-compose.production.yml up --build -d`.
5. Открой на firewall только необходимые публичные порты 80/443; порт 8080 не должен быть доступен извне. Caddy получит и будет обновлять TLS-сертификат автоматически.
6. Проверь доступность сайта из нескольких российских мобильных и фиксированных сетей. VPN-free доступность нельзя гарантировать до проверки выбранного провайдера и маршрутов.

Сайт пока не опубликован: для реального запуска нужны аккаунт хостинга, DNS и заполненные секреты окружения. Сам домен покупать необязательно, если хостинг предоставляет подходящий поддомен.

## Резервное копирование и безопасность

- Создать архив БД: `./scripts/backup-db.sh`. Восстановить: `./scripts/restore-db.sh backups/имя-файла.sql.gz` (операция перезаписывает содержимое целевой БД).
- Для production настрой ежедневный запуск backup-скрипта в cron и копирование архивов за пределы VPS; регулярно проверяй восстановление.
- Не публикуй `.env`, JWT secret или SMTP credentials.
- Пароли, токены подтверждения, сброса и сессий хранятся в виде хешей; сессии передаются через HttpOnly cookie.
- API проверяет членство в группе на каждом защищённом запросе; WebSocket повторно проверяет членство и отзывает доступ удалённых участников.
- Включены глобальный rate limit и более строгие лимиты на авторизацию.
- Перед эксплуатацией в РФ необходимо отдельно подготовить политику обработки персональных данных, согласие пользователя, определить оператора данных и проверить применимость требований 152-ФЗ.

## Структура

- `src/` — React frontend.
- `backend/` — NestJS API и Prisma schema/migrations.
- `deploy/nginx.conf` — reverse proxy для API, WebSocket и SPA.
- `docker-compose.yml` — PostgreSQL, backend и frontend.
- `docker-compose.production.yml`, `Caddyfile` — HTTPS через Caddy.
- `scripts/` — резервное копирование и восстановление PostgreSQL.
